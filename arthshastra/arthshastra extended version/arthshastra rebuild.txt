Here's exactly what was rebuilt and how each piece works:
portal/index.html + portal/css/portal.css — The entry point. Players land here before any game starts. Two states: new player (name + clan input, creates a localStorage profile) and returning player (shows their Samrat ID card with legacy score, win record, and 3 save slots with timestamps). Guest play is always available with no friction. The portal links to the 5 planned game sections — Campaign is live, the other four are labelled "Soon."
portal/js/auth.js — The full identity system. Creates and stores player profiles in localStorage. Handles 3 save slots per player, each storing a complete serialised game state. Title progression (Mantri → Raja → Maharaja → Samrat → Chakravarti → Dharmaraja) based on a cumulative legacy score that never resets. Legacy score is calculated from territories owned, dharma level, speed of campaign, and tech researched. Guest profiles persist in a separate key and can be promoted to full profiles without losing progress.
game/js/map.js — The SVG political map of Bharatvarsha 321 BCE. Five rendering layers: terrain backdrop (Himalayas, Deccan plateau, Thar desert, seas), river polylines (Ganga, Yamuna, Sindhu, Narmada, Mahanadi with labels), territory polygon fills colour-coded by owner, border strokes with selection glow, and transparent hit areas for click/hover. Zoom with mouse wheel, pan with drag, touch support. All territory labels render at 12–14px with dark background pills for legibility — the core fix from the original.
game/js/chanakya.js — The rule-based Chanakya AI. evaluateSituation() scans 25 different signal types across resources, territorial position, stat imbalances, turn progression, and research state — then ranks them by urgency. The response corpus has ~250 entries across 20 situation categories, plus 30 action-specific responses and dynamic territory-specific advice. A response tracker prevents the same line from repeating in a session. Every important response also includes an actual Sanskrit shloka from the Arthashastra. The final verdict at game end (title + narrative) is generated from the combination of territory percentage, dharma level, and turn count — so every game ending feels unique.
game/js/logic.js — Pure game logic, fully refactored. processTurnEnd() now handles faction AI (hostile factions grow in strength and occasionally raid your territories), neutral territory conversion from high influence, army upkeep consuming gold and food, dharma decay from large empires without governance, and happiness collapse from food shortages. All properly separated from rendering.
game/js/main.js — State hub. Wires all five modules together. Auto-saves to the active slot after every meaningful action. Passes full game state to Chanakya on every advisor call. Handles the portal ↔ game transition via sessionStorage (the portal writes the slot index, main.js reads it on load).
game/index.html — The game shell. All inline CSS (no external file needed for the game). The #map-container is now just an empty div — MapRenderer builds and injects the SVG itself. Text sizes bumped throughout (territory names at 12–14px, stat bars at 9px with proper contrast). The advisor panel now has a separate shloka line below the main quote.
